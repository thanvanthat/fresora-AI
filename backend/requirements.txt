# Fresora backend -- core.
#
#   py -m venv .venv
#   .venv\Scripts\activate          (Windows)
#   source .venv/bin/activate       (macOS/Linux)
#   pip install -r requirements.txt
#
# This set gives you the full OpenCV measurement pipeline, the documented
# freshness score, shelf-life estimation, storage guidance, the recipe engine
# and the assistant.
#
# Food identification runs on onnxruntime with the MobileNetV2 graph in models/,
# so it works out of this file alone -- no TensorFlow, and nothing to download
# on first run. That identifies the fruit and vegetables in ImageNet-1k.
#
# It CANNOT identify raw meat, poultry or fish: ImageNet-1k has no class for
# them, so the API still returns a truthful 503 for an unnamed photo of those
# and the app asks for the name. Adding those classes needs a trained head --
# see scripts/train_food_head.py.
#
# Version note: these lower bounds are what actually resolves to binary wheels
# on Python 3.14 (verified on 3.14.6). Older pins fail there -- pydantic-core
# has no cp314 wheel before 2.46 and pip falls back to compiling Rust. The
# floors are deliberately not upper-bounded so 3.11/3.12 users get wheels too.

fastapi>=0.141
uvicorn[standard]>=0.53
pydantic>=2.13
python-multipart>=0.0.32
httpx>=0.28

# Vision. OpenCV 5.x and 4.x are both fine: this codebase uses only long-stable
# APIs (cvtColor, threshold+Otsu, connectedComponentsWithStats, Laplacian).
opencv-python-headless>=4.10
numpy>=2.1
pillow>=11.0

# Food identification. onnxruntime is 24 MB against TensorFlow's ~600 MB, which
# is what makes identification deployable to a serverless function at all, and
# it publishes wheels for every Python version this project supports. The
# MobileNetV2 graph it runs lives in models/ and is committed.
onnxruntime>=1.20

# Tests
pytest>=8.3
pytest-asyncio>=1.0
